# Claude Code: пошаговая инструкция для новичка

Как с нуля собрать мультиагентную систему генерации возражений на иски дольщиков — с помощью **Claude Code** (не Cursor). Инструкция рассчитана на то, что ты Claude Code раньше **не открывала**.

---

## ⚠️ Сначала прочти: подойдёт ли тебе Claude Code из России

Это важно, потому что иначе ты упрёшься в стену на первом же шаге.

1. **Нужна платная подписка.** Claude Code не работает на бесплатном тарифе Claude.ai. Минимум — **Claude Pro** ($20/мес), есть Max ($100–200). Лимиты общие с обычным чатом Claude и сбрасываются в скользящем 5-часовом окне.
2. **Сетевая блокировка.** Claude Code (как и Anthropic API / Claude Desktop, которые у тебя уже недоступны) ходит на `api.anthropic.com`. Из России это домен блокируется на сетевом уровне. <cite index="2-1">Пользователи из России и ряда других стран сталкиваются и с сетевыми ограничениями, и с барьерами оплаты.</cite> Тебе понадобится стабильный способ обхода сетевого ограничения на уровне всей системы (не браузерное расширение, а системный туннель), иначе CLI просто не авторизуется и не сделает ни одного запроса.
3. **Оплата.** Российские карты Anthropic не принимает — это отдельный барьер, который придётся решать своими средствами.

> **Вывод честно:** если туннель + оплата у тебя уже решены (раз ты пользуешься Claude в этом интерфейсе — частично да), Claude Code тебе подойдёт и будет очень удобен. Если нет — в самом конце есть **План Б**: тот же агент на чистом Python + Google Gemini API (который у тебя уже работает для Shortread-дайджеста), без зависимости от Claude Code.

---

## Что вообще такое Claude Code и почему это меняет архитектуру

В прошлый раз мы проектировали агента на **LangGraph** — это Python-фреймворк, где *ты сама* пишешь граф из нод, а каждая нода дёргает LLM по API. Claude Code — это другое.

**Claude Code сам по себе уже агент.** Это не фреймворк, который ты импортируешь, а инструмент в терминале: ты пишешь ему задачу простым текстом, а он сам читает твои файлы, пишет код, запускает команды, проверяет результат. У него уже встроены: планирование (Plan Mode), вызов инструментов, и — главное для нас — **субагенты** (отдельные «Клоды» со своим контекстом) и **скиллы/слэш-команды** (твои сохранённые инструкции).

Отсюда **два пути**, и важно не путать их:

| | **Путь A — «Claude Code строит приложение»** | **Путь B — «Claude Code и есть агент»** |
|---|---|---|
| Что получаешь | Claude Code пишет тебе **Python-проект на LangGraph** (как в прошлый раз), который потом работает сам, без Claude Code | Сама мультиагентная система живёт **внутри Claude Code**: ноды = субагенты в `.claude/agents/`, оркестрация = слэш-команда |
| Когда уместно | Нужен автономный продукт, который крутится на сервере и обрабатывает иски пачками без твоего участия | Ты юрист-оператор: загружаешь иск, в терминале запускаешь `/vozrazhenie`, получаешь черновик. Полуавтомат с тобой в контуре |
| Зависимость от Claude Code | Только на этапе разработки. Готовый продукт от Claude Code не зависит | Постоянная: каждый запуск идёт через Claude Code |
| Сложность входа | Выше (нужно понимать LangGraph, разворачивать инфраструктуру) | Ниже (всё — markdown-файлы с инструкциями) |

**Моя рекомендация для тебя:** начни с **Пути B**. Он быстрее даёт работающий результат, идеально ложится на твой сценарий (один юрист, дела по одному), и попутно учит тебя Claude Code. Когда захочешь автономный продукт для нового LegalTech-стартапа — Путь A (промпт для него в файле `CLAUDE_CODE_PROMPT.md`, он попросит Claude Code построить тот самый LangGraph-проект).

Дальше инструкция ведёт по **Пути B**, а в конце — короткий блок про Путь A.

# ЧАСТЬ 1. Установка и первый запуск (15 минут)

## Шаг 1.1. Установи Claude Code

Открой терминал (на Windows честно проще всего через **WSL2** — Linux внутри Windows; PowerShell тоже работает, но Claude иногда генерирует Linux-команды, которые в нём спотыкаются).

Рекомендуемый способ — **нативный установщик** (не требует Node.js, сам обновляется):

```bash
# macOS / Linux / WSL2:
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell:
irm https://claude.ai/install.ps1 | iex
```

> ⚠️ Не устанавливай через `sudo`. И качай только с `claude.ai` — в 2026 были фейковые установщики через рекламу с малварью.

Проверь, что встало:
```bash
claude --version
```
Если команда не найдена — перезапусти терминал (бинарник должен попасть в PATH).

## Шаг 1.2. Авторизуйся

Из папки **любого проекта** (не пустой!) запусти:
```bash
claude
```
При первом запуске откроется браузер → войди в свой аккаунт Anthropic (Pro/Max). Токен сохранится в `~/.claude/credentials.json`.

> Если браузер не открывается / авторизация висит — это, скорее всего, та самая сетевая блокировка. Проверь, что твой системный туннель активен **до** запуска `claude`.

## Шаг 1.3. Освойся за 5 минут

Внутри сессии Claude Code (приглашение поменялось на `>`):
- Просто пиши задачи текстом: `объясни структуру этого проекта`.
- `/help` — список всех команд.
- `/model` — выбрать модель. Для архитектуры и кода бери **Opus**, для рутины — **Sonnet** (экономит лимит).
- **Shift+Tab** — включить **Plan Mode**: Claude сперва покажет план, ты утвердишь, и только потом он что-то делает. **Всегда** используй Plan Mode для нашего проекта.
- `/clear` — очистить контекст между разными задачами.
- По умолчанию Claude **спрашивает разрешение** перед изменением файла или запуском команды. Не отключай это первое время.

> Совет новичку: первую неделю поиграй с Claude Code на чём-нибудь неважном, чтобы понять, как быстро тратится лимит, прежде чем грузить его юридическим проектом.

# ЧАСТЬ 2. Создаём каркас проекта (Claude Code сделает это за тебя)

Идея: ты **не пишешь код руками**. Ты даёшь Claude Code чёткое ТЗ, он создаёт структуру файлов. Твоя работа — проверять и направлять.

## Шаг 2.1. Подготовь папку

В обычном терминале (вне Claude):
```bash
mkdir vozrazheniya-agent && cd vozrazheniya-agent
mkdir -p data/cases data/knowledge_base
```
Скопируй сюда свои 5 дел (иск + ДДУ + эталонные возражения) — иски и ДДУ в `data/cases/`, **эталонные возражения** в `data/knowledge_base/` (это будущие few-shot примеры).

## Шаг 2.2. Создай «конституцию» проекта — `CLAUDE.md`

Это самый важный файл. <cite index="16-1">CLAUDE.md — «конституция» агента, главный источник правды о том, как устроен твой репозиторий. Claude читает его в начале каждой сессии и опирается на него, чтобы ты не объясняла проект заново.</cite>

Создай в корне файл `CLAUDE.md` со следующим содержимым (можешь прямо попросить Claude Code: «создай CLAUDE.md по этому тексту»):

```markdown
# Проект: Генератор возражений на иски дольщиков (214-ФЗ)

## Что это
Мультиагентная система. Сторона — ЗАСТРОЙЩИК (ответчик). На вход — исковое
заявление дольщика (часто скан) + ДДУ. На выход — ПРОЕКТ возражений (.docx),
обязательно проверяемый юристом.

## КРИТИЧЕСКИЕ ПРАВИЛА (соблюдать всегда)
1. Вывод — ПРОЕКТ для юриста, НЕ финальный документ. На каждом — дисклеймер.
2. Все суммы, неустойки, проценты, периоды просрочки считает ТОЛЬКО
   детерминированный Python-код. LLM арифметику НЕ делает — это запрещено.
3. Перед любой отправкой текста иска/ДДУ во внешнюю модель — ОБЕЗЛИЧИВАНИЕ ПДн
   (паспорта, ФИО, адреса, телефоны, ИНН, СНИЛС). Восстановление — только
   локально в финальном .docx.
4. Каждый юридический тезис в документе должен иметь источник (норма, дело,
   расчёт). Утверждения без источника — недопустимы.

## Предметная область
Типы требований истца (комбинируются): возмещение расходов на устранение
недостатков / уменьшение цены; неустойка за недостатки; неустойка за просрочку
передачи объекта; штраф; моральный вред; судебные расходы.
Ключевые нормы: ФЗ-214 (ст.7, ч.4 ст.10 — лимит 3% цены договора),
ст.333 ГК РФ (снижение неустойки), ПП РФ № 326 (отсрочка исполнения).
ВНИМАНИЕ: редакции ПП-326 и мораториев меняются — проверять актуальность.

## Структура документа возражений (по эталонам)
Шапка → 1.Фактические обстоятельства → разделы по каждому требованию →
ходатайство об отсрочке → ПРОШУ СУД → Приложения.

## Технологии
Python 3.11+. Расчёты — чистый Python. OCR — Tesseract (rus).
Обезличивание — Natasha + regex. Документ — python-docx.
RAG по эталонным возражениям — опционально (Chroma).

## Команды
- Тесты калькуляторов: `pytest tests/`
- Прогон на деле: `python run.py data/cases/<дело>`

## Стиль
Низкая температура для юртекста. Код с типами и docstring. Комментарии по-русски.
```

> Лайфхак: в любой момент можно дописать правило в память командой с `#` прямо в чате, например: `# всегда проверяй редакцию ПП-326 на актуальность`.

## Шаг 2.3. Попроси Claude Code построить каркас

Запусти `claude`, **включи Plan Mode (Shift+Tab)** и дай команду (она же лежит в `CLAUDE_CODE_PROMPT.md`, можешь скопировать оттуда):

> «Прочитай CLAUDE.md. Создай каркас Python-проекта: детерминированные инструменты (калькулятор неустойки/лимита 3%/ст.333, обезличиватель ПДн на Natasha+regex, OCR на Tesseract, генератор .docx по структуре из CLAUDE.md), папки для промптов и тестов. Пока без логики агентов — только инструменты и тесты к калькуляторам. Покажи план, прежде чем создавать файлы.»

Claude покажет план → проверь его → утверди. Он создаст файлы и спросит разрешение на каждый. После — попроси: «запусти pytest и убедись, что тесты калькуляторов проходят».

**Почему именно так:** инструменты (особенно калькулятор) — это детерминированный фундамент, который никогда не должен галлюцинировать. Его делаем и тестируем первым, до всякой магии с агентами.

# ЧАСТЬ 3. Сердце системы — субагенты (= наши ноды)

Вот ключевая идея Пути B: **каждая нода из твоей схемы — это субагент Claude Code.**

<cite index="16-1">Субагенты выносят работу специализированным агентам, которые возвращают только итог, сохраняя основной контекст чистым.</cite> Это ровно то, что нам нужно: Аналитик, Планировщик, Исследователь и т.д. — каждый со своим узким промптом и своим контекстом.

<cite index="17-1">Кастомные субагенты описываются в `.claude/agents/` (для проекта) как markdown-файлы с YAML-frontmatter. Параллельно может работать до 10 субагентов.</cite>

## Шаг 3.1. Важное правило безопасности субагентов

<cite index="18-1">Рекомендуемый паттерн — давать субагентам только инструменты для чтения (убрать Edit, Write из списка tools в frontmatter), а всю работу с записью файлов и Bash оставлять родительскому агенту, который умеет показывать запросы на подтверждение.</cite>

Значит: субагенты-аналитики **анализируют и возвращают текст/JSON**, а файлы (.docx) пишет либо родительский агент, либо отдельный шаг с твоим подтверждением.

## Шаг 3.2. Создаём субагентов

Структура (Claude Code создаст её по твоей просьбе):
```
.claude/
  agents/
    analyst.md       # Аналитик
    planner.md       # Планировщик
    researcher.md    # Исследователь
    critic.md        # Критик
    generator.md     # Генератор
  skills/
    vozrazhenie/
      SKILL.md       # оркестратор = слэш-команда /vozrazhenie (роль Супервизора)
```

> Почему нет отдельных файлов «Интервьюер» и «Супервизор»?
> - **Супервизор** в Claude Code — это не субагент, а **сам управляющий слой**: его роль играет слэш-команда-оркестратор (`SKILL.md`), которая по шагам вызывает остальных и решает, что дальше. Claude Code изначально устроен как «оркестратор + рабочие», так что Супервизор у нас встроенный.
> - **Интервьюер** — это не отдельный агент, а **естественная пауза**: когда данных не хватает, оркестратор просто задаёт тебе вопрос прямо в терминале и ждёт ответа. Claude Code интерактивен по природе, отдельная нода не нужна. (В Пути A на LangGraph Интервьюер — настоящая нода через `interrupt`, потому что там нет живого диалога.)

Содержимое каждого файла субагента — в файле `CLAUDE_CODE_PROMPT.md` (раздел «Промпты субагентов»). Формат каждого:
```markdown
---
name: analyst
description: Декомпозирует исковое заявление дольщика, извлекает требования, суммы, даты. Вызывать в начале обработки каждого дела.
tools: Read, Grep, Glob          # только чтение — никакого Write/Edit
model: sonnet                    # аналитику хватит Sonnet; критику можно opus
---

Ты — Аналитик. На вход — текст искового заявления (уже обезличенный).
Извлеки строго в JSON: суд, № дела, истец/ответчик, данные ДДУ (номер, дата),
дату передачи объекта, цену договора, и список требований по типам
(defects, penalty_defects, penalty_delay, fine, moral, legal_costs) — с суммой
и дословной цитатой-основанием из иска. Не выдумывай суммы. Нет данных → null.
```

## Шаг 3.3. Создаём оркестратор-команду `/vozrazhenie` (это Супервизор)

Файл `.claude/skills/vozrazhenie/SKILL.md` описывает весь конвейер. <cite index="12-1">Слэш-команда может оркестрировать поведение: прямо в ней прописывается, что нужно поднять субагента (или конкретного субагента), вызвать определённый скилл/воркфлоу и выстроить работу в пайплайн (research → scan → write), а не пытаться сделать всё за один проход.</cite>

Скелет (полная версия — в `CLAUDE_CODE_PROMPT.md`):
```markdown
---
name: vozrazhenie
description: Полный конвейер генерации возражений на иск дольщика. Принимает путь к папке дела.
disable-model-invocation: false
---

# Конвейер возражений (роль Супервизора)

Дано: путь к папке дела ($ARGUMENTS) с иском и ДДУ.

Выполни ПО ПОРЯДКУ, контролируя результат каждого шага:

1. ПОДГОТОВКА: запусти OCR (tools/ocr.py) на иске и ДДУ. Если confidence OCR
   низкий — СПРОСИ меня, подтвердить ли ключевые данные (это роль Интервьюера).
2. ОБЕЗЛИЧИВАНИЕ: прогони тексты через tools/anonymizer.py. Дальше работай
   ТОЛЬКО с обезличенным текстом.
3. АНАЛИЗ: вызови субагента `analyst` → получи JSON с требованиями.
4. ПЛАН: вызови субагента `planner` → список разделов и пробелы в данных.
   Если есть пробелы — СПРОСИ меня (Интервьюер).
5. ИССЛЕДОВАНИЕ: для каждого требования вызови субагента `researcher`. Он
   обязан: считать суммы через tools/penalty_calculator.py (НЕ сам!), искать
   аргументы в data/knowledge_base/, ссылаться на нормы.
6. ГЕНЕРАЦИЯ: вызови субагента `generator` → черновик разделов.
7. КРИТИКА: вызови субагента `critic`. Если есть блокеры (суммы без источника,
   пропущенные требования) — вернись к шагу 5 или 6. Максимум 3 круга.
8. СБОРКА: собери .docx через tools/docx_writer.py, восстанови ПДн локально,
   добавь дисклеймер «ПРОЕКТ. Требует проверки юристом». Покажи путь к файлу.

Правила: суммы — только из калькулятора; каждый тезис — с источником;
не пропусти ни одного требования из анализа.
```

Запусти `claude` и попроси создать эти файлы по образцам из `CLAUDE_CODE_PROMPT.md`. Проверь, что команда видна: набери `/` — в списке должна появиться `/vozrazhenie`.

# ЧАСТЬ 4. Запуск на реальном деле

## Шаг 4.1. Первый прогон

В сессии Claude Code:
```
/vozrazhenie data/cases/case_2
```
(`case_2` — самое полное дело: неустойка + недостатки.)

Что будет происходить:
1. Claude запустит OCR и обезличивание.
2. Вызовет Аналитика — увидишь извлечённые требования.
3. Если что-то неясно — **задаст тебе вопрос прямо в терминале** (Интервьюер). Отвечаешь текстом.
4. Прогонит Исследователя, Генератора, Критика по кругу.
5. Соберёт `.docx` и покажет путь.

## Шаг 4.2. Что проверить на первом деле
- [ ] Аналитик нашёл **все** требования (в case_2 их 6).
- [ ] Суммы в документе совпадают с иском и посчитаны калькулятором, не моделью.
- [ ] Есть все нужные разделы + лимит 3% + ст.333 + отсрочка по ПП-326.
- [ ] Критик отработал и дал «PASS» (или внятный список замечаний).
- [ ] На документе есть дисклеймер про юриста.
- [ ] В тексте, ушедшем в модель, **не было** реальных ПДн (проверь логи обезличивателя).

## Шаг 4.3. Итерируй
Если что-то не так — не лезь править код руками. Скажи Claude Code:
> «Аналитик пропустил требование о штрафе. Посмотри analyst.md и его выход на case_2, найди причину, поправь промпт и прогони заново.»

Это и есть рабочий цикл с Claude Code: **ты ставишь задачу и проверяешь, он копается в коде.**

# ЧАСТЬ 5. Полезные приёмы Claude Code для этого проекта

- **Plan Mode (Shift+Tab) — всегда** на сложных шагах. Для юрпроекта цена ошибки высока, лучше сперва посмотреть план.
- **`/model`**: Аналитик/Планировщик — Sonnet (дёшево), Критик и сборка аргументации — Opus (качество). Экономит лимит.
- **`/clear`** между разными делами, чтобы контекст одного иска не «протекал» в другой.
- **`/agents`** — посмотреть/поправить субагентов через интерфейс.
- **`/cost`** или `/usage` — следить за расходом лимита (он у тебя общий с обычным чатом и не бесконечный).
- **Hooks (на потом):** можно повесить хук, который после сборки .docx автоматически прогоняет проверку «есть ли дисклеймер и все разделы». Но это уже оптимизация — сначала добейся работающего базового конвейера.
- **Git:** заведи git в проекте с первого дня. Claude Code иногда меняет файлы массово; коммит после каждого рабочего шага — твоя страховка. Добавь `.claude/credentials.json` в `.gitignore`.

# План Б: если Claude Code недоступен из-за блокировок/оплаты

Если туннель/оплата не решаются — не теряй проделанное проектирование. Тот же агент собирается на **чистом Python + LangGraph + Google Gemini API** (Gemini у тебя уже работает для Shortread-дайджеста как Россия-доступная альтернатива).

Разница минимальна:
- Архитектура (ноды, супервизор, инструменты, обезличивание, детерминированные расчёты) — **та же**, она в файле `IMPLEMENTATION_GUIDE_LANGGRAPH.md` (это твоя прошлая инструкция, она остаётся валидной).
- Вместо `langchain-anthropic` ставишь `langchain-google-genai`, в `llm.py` провайдер — Gemini.
- Claude Code тут не нужен вовсе: пишешь проект в любом редакторе (хоть в этом чате по кускам), запускаешь `python run.py`.

То есть Путь B (Claude Code) — это про **удобство и скорость**, а План Б — про **независимость от инфраструктуры Anthropic**. Проектные решения у них общие.

# Краткое резюме: с чего начать прямо сейчас
1. Реши вопрос с туннелем + оплатой. Не решается → План Б (Gemini + LangGraph).
2. Установи Claude Code, авторизуйся, поиграй 10 минут на пустяках.
3. Создай папку, скопируй 5 дел, напиши `CLAUDE.md` (текст выше).
4. Попроси Claude Code построить инструменты (калькулятор, обезличиватель, OCR, docx) + тесты. Прогони `pytest`.
5. Создай 5 субагентов и команду `/vozrazhenie` по образцам из `CLAUDE_CODE_PROMPT.md`.
6. Запусти `/vozrazhenie data/cases/case_2`, проверь по чек-листу, итерируй.
